日志应回答何时、何处、发生何事以及关联请求，不记录密码、令牌或不必要个人数据；统一字段、时区、保留期和访问权限。

**定义：** 结构化日志把运行事件以机器可解析字段保存，支持排障、审计和监控。
可关联分布式请求并提升检索效率，同时避免敏感信息无控制扩散。

**机制 / 关键点：** 级别需一致使用，时间戳含时区，关联 ID 不应包含用户秘密；日志保留和访问应符合隐私法规。

**实际示例：** 记录请求 ID、服务名、错误类别和耗时，而非将完整授权头或用户密码写入错误日志。例如一条示意记录可有时间、请求 ID、路由模板 `/orders`、状态 503 和耗时 143 ms；排查时用请求 ID 关联上下游事件，避免把 URL 查询参数、Cookie 或请求正文整段复制到日志。

**常见误区：** “内部日志无需脱敏”“Debug 级永远可开”“删除业务记录等于删除日志副本”均不成立。

**可操作步骤：** 制定字段白名单、脱敏规则、访问控制与保留计划；在测试中用扫描验证敏感字段不落日志。

**边界 / 何时求助专业人士：** 安全事件调查、个人信息处理和合规留存由安全、隐私与法务团队共同确定。

**注意：** 保留期限与个人信息规定依辖区及业务变化。

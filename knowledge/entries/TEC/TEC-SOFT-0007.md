**用途与判断：** 响应慢可能来自 CPU、锁等待、I/O、内存分配或下游依赖；先定义用户可感知指标和稳定负载，再用剖析数据判断瓶颈，不凭单条慢请求重写算法。

**现场实操**：报表接口 P95 延迟变高，采样剖析显示大部分 CPU 用在重复 JSON 序列化。先对相同数据集记录基线，优化序列化和缓存后用相同负载比较延迟、CPU 与内存，确认没有改变输出语义。

如果接口总耗时 2 秒，而 CPU 剖析只覆盖线程运行时的 200 毫秒，不能据此把剩余时间都归为计算；还要查看数据库、网络及锁等待。对比优化前后应使用相同输入、并发量、机器和采样方法，并看尾延迟及错误率是否改善。

**可操作步骤：** 固定输入与环境、采集火焰图或运行时 profile；区分 CPU profile、内存 profile 和阻塞 profile；一次改一项并保留基准及回归测试。

> **操作红线**：剖析器有开销，生产采样须经授权并脱敏；微基准结果不能直接代表线上吞吐。

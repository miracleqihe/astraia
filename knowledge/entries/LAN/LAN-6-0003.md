语言模型把输入切成 token，再将 token 映射为模型可处理的编号；token 可能是整词、子词、字符或字节片段。切分结果取决于具体分词器和训练设计，不等同语言学中的词或文字字符。不同语言的 token 成本和覆盖能力可能差异明显。

**定义：** 分词器是把文本映射为模型词表单位及编号的预处理系统。

它解释模型上下文长度、输入费用、拼写错误和低资源语言效果为何受分词方式影响。

**机制 / 关键点：** 子词方法通过词表和合并规则压缩常见片段；字节级方案可覆盖广泛文本，但表示长度仍不均匀。分词器更新会改变同一文本的 token 序列。

**例子 / 文本 / 观察示例：** 同一汉字短语在两个模型 tokenizer 中可能产生不同 token 数；比较时需使用对应版本的分词器，而非用字符数推算上下文占用。

**词和 token 不必一一对应。** 仅作示意，假设词表允许，“天气晴朗”可以按“天气／晴朗”切成两个片段，也可以按四个汉字切分；实际结果由具体分词器决定。部分分词器还会记录空格和进行文本规范化，因此同样的可见句子、前后空格和具体模型版本都可能影响最终编号与数量；需要精确计数时应运行所用模型对应的分词器。

**常见误区**

- 把 token 当作词、汉字或语素的固定等价物。
- 认为每种语言平均每词占用相同 token 数。
- 忽略 tokenizer 版本而比较模型输入长度。

**注意：** tokenizer 规范属于具体模型实现，且可能随版本更新。涉及成本或公平性结论时应记录模型、词表和测试语料，不把切分差异解释为语言价值高低。
